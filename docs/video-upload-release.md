# Video upload release checklist

New clips and thumbnails upload directly to permanent, write-once keys in private R2. `publish-upload` submits both to Sightengine and creates a post only on approval; there is no media copy. The Worker at `clips.handstrudel.com` checks public visibility in Supabase before serving any bytes, including internal cache hits. Its public response is `no-store`; hiding a clip blocks new requests without a cache purge. The cache is not exposed as a URL. Existing clips and avatars stay on the legacy public media domain. The iOS original stays in Private drafts.

## Production setup

1. Reuse `handstrudel-video-staging` (the bucket name is historical). Keep public `r2.dev` disabled and do not attach a public R2 custom domain. **Remove the former one-day object expiry before enabling uploads**: approved files now remain in this bucket. Create a bucket-scoped Object Read & Write credential for the Edge Functions. Leave legacy media credentials unchanged.
2. Set `R2_VIDEO_STAGING_BUCKET`, `R2_VIDEO_STAGING_ACCESS_KEY_ID`, `R2_VIDEO_STAGING_SECRET_ACCESS_KEY`, `SIGHTENGINE_API_USER`, and `SIGHTENGINE_API_SECRET` in the Edge Function secrets. Generate a high-entropy `VIDEO_MAINTENANCE_TOKEN` for the Worker and the Edge Function to share. Keep `VIDEO_UPLOADS_ENABLED` unset or `false` during setup.
3. Apply `20261115020000_screen_public_video_uploads.sql` and deploy `sign-upload`, `publish-upload`, `delete-video`, and `delete-account` with the repo's JWT configuration. Deploy the Worker with `npx wrangler deploy --config cloudflare/clip-media/wrangler.toml`; set its `SUPABASE_PUBLISHABLE_KEY` and `VIDEO_MAINTENANCE_TOKEN` with Wrangler secrets. The playback lookup never needs a service-role key. Do not override `no-store` with a Cloudflare cache rule on the clip hostname. Set `MEDIA_CACHE_TTL_SECONDS=0` to disable internal caching without changing the visibility checks.
4. Publish the web update and use a new iOS build before enabling uploads. Older builds can still play legacy posts, but do not understand the new private clip URLs or upload contract. Leave general uploads disabled and set `VIDEO_UPLOADS_SMOKE_USER_ID` to a dedicated test account's profile UUID for the hosted smoke test. Confirm a clean clip and thumbnail play on iOS, the watch page, and the embed; verify seeking, unsigned R2 reads failing, and repeated PUTs being rejected. Confirm a held clip and a simulated scanner failure stay off every playback path, and that hiding a clip denies new requests after warming the cache. Verify the Worker cron runs, remove the smoke account and secret, and confirm the app's reports reach the assigned reviewer before opening uploads.

If checks fail, turn `VIDEO_UPLOADS_ENABLED` off. Do not restore direct client inserts as a rollback. The Worker cron checks for interrupted or retryable screening jobs every two minutes, up to three attempts per reservation. It also removes unused private uploads after 24 hours, safely past the signed PUT expiry. Published clips are exempt while the video row exists. Keep the Worker in place for viewing even when posting is paused. If Supabase is unavailable, new playback requests fail closed with HTTP 503.

Sightengine's stored-video endpoint samples at a configurable interval; this release uses its documented 0.5-second option and a starting 0.5 threshold for `sexual_activity` and `sexual_display`. This is not frame-complete, and these are classifier scores, not guarantees. Keep reporting and blocking available, and do not enable posting if live verification fails.

## November 15 smoke test

- Created and configured the private staging bucket. A Cloudflare account-authenticated write and read matched byte-for-byte; R2 rejected the unsigned read, and the test object was removed. The existing public-media S3 credential returned R2 `403 AccessDenied` on both presigned and directly signed writes to staging. The local gate now expects a separate staging-only key. Do not rotate or broaden the public key.
- The hosted Sightengine image check succeeded with the configured secrets. Both video requests returned HTTP 400, `usage_limit:3701`, on the current plan. No clean/flagged video verdict was available.
- The test created no public posts. The temporary authenticated function and its one-time credential were removed and verified absent. The upload flag remained unset, and the publication functions and migration were not deployed.
